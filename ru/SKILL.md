# Be-Ambitious Harness

Три роли и один человек. **Планировщик** превращает задачу в промпт с двумя планками и входной проверкой. **Воркер** выполняет промпт, начиная с проверки. **Верификатор** оценивает результат, видя только критерии и факты. **Человек** выбирает схему и предел затрат — это не делегируется.

Каждая роль читает только свои файлы. Это намеренно: соблюдение инструкций рушится после 5–6 одновременных ограничений, поэтому структура задаётся файлами и шаблонами, а не правилами, которые нужно удерживать в голове.

## Поток

**0. Приём.** Собери четыре поля: `задача`, `контекст`, `режим` (сохранить масштаб / амбициозное расширение / рекомендовать), `стоп_после_разбора` (да/нет). Незаполненные — по умолчанию: рекомендовать, нет.

**1. Маршрут.** Открой `scenarios/_index.md`, выбери сценарий по сигналам. Сомнение между двумя — бери тот, где лежит результат. Ни один — `generic.md`.

**2. Разбор и промпт.** Прочитай `agents/planner.md` и файл сценария. Выполни разбор; подсказки сценария — для соответствующих пунктов, не для всех сразу. Выдай вопросы и промпт по `core/prompt-template.md`. При `стоп_после_разбора = да` остановись после разбора и вопросов; продолжай только после ответа человека.

**3. Предполётная проверка.** Прогони промпт по `checklists/pre-flight.md`. Любой «нет» — вернись к шагу 2.

**4. Воркер.** Новая сессия или субагент. Передай: промпт, материалы, блок «Для воркера» из сценария, `agents/worker.md`, `core/gate.md`, `core/report-format.md`. Ничего из разбора.

**5. Верификатор.** Отдельная сессия, желательно другая модель. Передай: разделы 1, 2, 4, 6 промпта, результат, материалы, журнал свидетельств воркера, `agents/verifier.md`, `core/report-format.md`, `tools/gate-check.py`. Разделы 3, 5, 7, рассуждения воркера и разбор планировщика остаются у тебя.

**6. Приёмка.** Прогони `checklists/post-run.md`. Человеку — результат, вердикт верификатора и список непроверенного. Решение «принять / доработать / остановиться» — его.

## Правила харнесса

- Обязательные требования исходной задачи проходят через все этапы дословно.
- Критерии приёмки и критерий входной проверки фиксируются на шаге 2 и дальше только читаются.
- Работа, специфичная для амбициозной ветки, начинается после зафиксированного исхода входной проверки.
- Верификатор не исправляет. Воркер не оценивает себя вместо верификатора.
- Любой этап, которому не хватает материалов, запрашивает их у человека и ждёт — это не исход проверки.

## Файлы

- `agents/` — инструкции ролей: `planner.md`, `worker.md`, `verifier.md`
- `core/` — общие определения: `gate.md`, `prompt-template.md`, `report-format.md`
- `scenarios/` — предметные подсказки: `_index.md` и шесть сценариев
- `checklists/` — `pre-flight.md`, `post-run.md`
- `evals/` — тестовые задачи и карта оценки самого харнесса; гоняй после любой правки
