# Приёмка после прогона

Прогоняется оркестратором, когда есть отчёт воркера и вердикт верификатора. Результат — пятистрочный отчёт для человека по `core/report-format.md`.

## Целостность процесса

- [ ] Воркер не получал разбор планировщика; верификатор не получал рассуждения воркера и разделы 1, 3, 4, 5, 7.
- [ ] Верификатор — другая сессия; если та же модель, это отмечено в отчёте человеку.
- [ ] Если была входная проверка: блок GATE есть в журнале, стоит раньше первого действия амбициозной ветки, критерий в нём совпадает с разделом 4 дословно.
- [ ] Если воркер запрашивал материалы — запрос был до работы, не оформлен как исход «данных недостаточно».

## Сверка отчётов

- [ ] Каждое требование раздела 2 — есть строка в вердикте верификатора.
- [ ] Каждый критерий раздела 6 — измерен верификатором своим способом или помечен «не проверить» с причиной.
- [ ] Значения воркера и верификатора по критериям сопоставлены; расхождения перечислены.
- [ ] Тест на опровержение выполнен; результат записан.
- [ ] Список «не проверено» воркера и «не проверено» верификатора объединён; дубли сведены.

## Границы

- [ ] Изменения вне раздела 2 (если есть) перечислены воркером с обоснованием.
- [ ] Признаки подгонки под метрику проверены верификатором; результат записан.

## Для человека

- [ ] Пять строк: что сделано; схема и исход проверки; вердикт; что не проверено; какое решение требуется.
- [ ] Если исход gate «пройдена» при незаданном пределе затрат — оценка затрат на амбициозную ветку приложена, решение вынесено человеку.
- [ ] Если вердикт «отклонить» — дефекты перечислены с предложениями; следующий шаг (доработка / остановка) — выбор человека, не оркестратора.

## Обратная связь харнессу

- [ ] Что из сценария не сработало или не понадобилось — одна строка в `evals/scorecard.md` для этого прогона.
