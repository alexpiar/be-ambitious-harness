# Предполётная проверка промпта

Прогоняется планировщиком перед выдачей и оркестратором перед передачей воркеру. Любой «нет» — промпт возвращается на доработку.

## Структура

- [ ] Первая строка — имя сценария из `scenarios/`.
- [ ] Разделы 1, 2, 3, 5, 6, 7 присутствуют в этом порядке.
- [ ] Раздел 4 присутствует тогда и только тогда, когда схема условная.
- [ ] В промпте только разделы шаблона; разбор, отклонённые варианты и история выбора в нём отсутствуют.

## Содержание

- [ ] Раздел 1 называет, что должно стать возможным или произойти, — не только артефакт.
- [ ] Раздел 1 называет схему и планку одной строкой.
- [ ] Раздел 2 — обязательные требования перенесены дословно (сверь с исходной задачей построчно).
- [ ] Раздел 3 — необходимые и необязательные материалы разделены; есть строка о запросе до начала работы.
- [ ] Раздел 6 — критерии измеряют цель; есть эталон или исходный уровень; есть тест на опровержение; есть способ независимой проверки, который можно выполнить без воркера.
- [ ] Численные цели помечены: обязательные — в критериях, экспериментальные — как гипотезы.
- [ ] Поля `[...]` стоят только там, где человек может их заполнить; у каждого понятно, что вписать.

## Входная проверка (для условной схемы)

- [ ] Все пять атрибутов из `core/gate.md`: действие, наблюдаемый результат, критерий, предел затрат, три исхода.
- [ ] Критерий — наблюдаемый (число, факт, артефакт), не мнение.
- [ ] Предел затрат существенно меньше работы, которую проверка разрешает.
- [ ] Для исхода «пройдена» указано: предел затрат на амбициозную ветку задан — или базовая плюс отчёт.
- [ ] Есть фраза о порядке: амбициозная работа — после зафиксированного исхода.

## Самодостаточность

- [ ] Промпт понятен без этого разговора: нет ссылок на «как обсуждали», «см. выше», имена из разбора.
- [ ] Весь контекст, нужный воркеру, внутри промпта или в перечисленных материалах.

## Вопросы

- [ ] Не больше трёх; каждый меняет схему, критерий или предел затрат; на каждый человек может ответить.
