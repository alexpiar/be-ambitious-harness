# Be-Ambitious Harness

Харнесс для амбициозной постановки задач ИИ-агентам. Развитие промпта Феликса Ризеберга «deeper, not bigger» в трёхролевой процесс: планировщик строит промпт с двумя планками и входной проверкой, воркер выполняет его начиная с проверки, верификатор оценивает результат по критериям, не видя рассуждений воркера. Человек выбирает схему и предел затрат.

## Зачем харнесс, а не промпт

Один промпт со всеми правилами упирается в три известных ограничения: соблюдение инструкций рушится после 5–6 одновременных ограничений; негативные формулировки праймят то, что запрещают; модель оценивает знакомый текст выше, чем чужой. Харнесс разводит это по файлам: каждая роль читает только своё, сценарий добавляет подсказки только для своего типа задач, верификатор получает факты без контекста автора.

## Структура

```
be-ambitious-harness/

│   ├── planner.md        разбор (4 пункта) → промпт
│   ├── worker.md         порядок выполнения, журнал
│   └── verifier.md       порядок проверки, вердикт
├── core/
│   ├── gate.md           входная проверка: 5 атрибутов, 3 исхода, порядок
│   ├── prompt-template.md  7 разделов, скелет
│   └── report-format.md  отчёт воркера, вердикт верификатора, отчёт человеку
├── scenarios/
│   ├── _index.md         маршрутизация
│   ├── design-ux.md
│   ├── data-analysis.md
│   ├── code-engineering.md
│   ├── writing-research.md
│   ├── decision-plan.md
```

## Установка

Как скилл Claude Code: скопируй папку в `~/.claude/skills/be-ambitious-harness/` (или в `.claude/skills/` проекта). Вызов — `/be-ambitious-harness` или фраза «сделай задачу глубже». Другие агенты: укажи на `SKILL.md` как на точку входа.

## Минимальный прогон

1. Задача + контекст + режим → планировщик по `agents/planner.md` и файлу сценария.
2. Промпт → `checklists/pre-flight.md`.
3. Промпт + материалы + блок «Для воркера» + `agents/worker.md` + `core/gate.md` + `core/report-format.md` → воркер в новой сессии.
4. Разделы 2 и 6 + результат + журнал + `agents/verifier.md` + `core/report-format.md` → верификатор в новой сессии, желательно на другой модели.
5. `checklists/post-run.md` → пять строк человеку.

Для задачи на пять минут харнесс не нужен. Для задачи, где амбициозная ветка стоит дня работы, — нужен.

## Что ещё не проверено

Харнесс написан, но не прогнан. Первое, что стоит сделать, — T1, T3 и L2 из `evals/tasks.md`: они проверяют три поведения, которые нельзя оценить чтением — начинает ли воркер с проверки, пишет ли тест до фикса, пересматривает ли критерий по данным. Правки — по результатам, в `scorecard.md`.

Известные пробелы:
- Нет сценария для мультимодальных задач (видео, аудио, 3D).
- Нет механизма для многодневных задач с несколькими gate подряд.
- Верификатор на другой модели — рекомендация; механизм выбора модели зависит от среды.

## Источники

- Felix Rieseberg, [How to be more ambitious: A tutorial for humans with models](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/) — четыре типа амбиции, приёмы, исходный промпт.
- Vasileva, [Large Language Models Can Follow Instructions, But Not Many at Once](https://icml.cc/virtual/2026/69314) — порог 5–6 ограничений.
- Rana, [Semantic Gravity Wells: Why Negative Constraints Backfire](https://arxiv.org/html/2601.08070v1) — негативные инструкции.
- Wataoka et al., [Self-Preference Bias in LLM-as-a-Judge](https://arxiv.org/abs/2410.21819v1) — самооценка и перплексия.
- Locke & Latham; Seijts & Latham — конкретные трудные цели; learning goals для новых задач.
- Ordóñez et al., Goals Gone Wild — подгонка под метрику при стретч-целях.
- [Ask or Assume?](https://ucrisportal.univie.ac.at/en/publications/ask-or-assume-uncertainty-aware-clarification-seeking-in-coding-a/) — отделение детекции недоопределённости от исполнения.
