# Оценщик прогона

Слепая оценка пары прогонов одной задачи: два плеча — например, харнесс и одиночный скилл или две версии харнесса. Первая часть — для оркестратора; вторая передаётся оценщику целиком.

## Оркестратор: как проводится оценка

1. **Пакеты.** Для каждого плеча — итоговые артефакты, журналы, отчёты, вердикт проверки, если был, и выписки действий, собранные скриптом из журналов сессий. Имена плеч, упоминания харнесса и скилла вычищены; пакеты называются X и Y.
2. **Два вызова в обратном порядке.** Каждая пара оценивается дважды, отдельными сессиями без общего контекста. В первом вызове X — плечо, выпавшее по монете; во втором буквы меняются местами. X всегда показывается первым. Соответствие букв плечам — в `scoring/<ID>-mapping.txt` до первого вызова.
3. **Сведение** — по плечам, буквы переводятся по соответствию. По каждому пункту и плечу: значения двух вызовов совпали — это значение; не совпали — Unknown. Сравнение по сути: оба вызова назвали лучшим одно плечо — оно; иначе Unknown, а не победитель. Оценка 0–1 пересчитывается по сведённым пунктам.
4. **Сравнение прогонов.** Не только средняя оценка: какие задачи перевернулись между двумя прогонами — итог задачи pass → fail или fail → pass.
5. **Оценщику не передаются:** эталон задачи ([evals/reference/](../../evals/reference/README.md)), имена плеч и соответствие букв, рассуждения исполнителей вне артефактов, ожидаемый исход из протокола, результат другого вызова. Оценщик — сессия, не участвовавшая в прогоне, желательно на другой модели.

## Оценщик: инструкция

Ты — оценщик, не участвовавший в прогоне. Ты оцениваешь два пакета, X и Y, по рубрике. Оценка — свидетельства, а не впечатление. Кто сделал пакет, тебе не сказано; не угадывай.

**Получаешь:** постановку задачи и её условия «Провал» из `evals/tasks.md`; применимые строки `evals/scorecard.md` и правило, как они применяются к плечу без отдельных ролей; пакеты X и Y; скрытый оракул и команду запуска, если оракул есть.

**Порядок.**
1. Прочитай рубрику до пакетов.
2. По каждому пункту рубрики и каждому пакету — одно значение со свидетельством: файл и строка, номер вызова в выписке действий, вывод команды.
   - **pass** — условие «Провал» не сработало; строка карты — «да»; оракул — порог выполнен.
   - **fail** — условие сработало; строка — «нет»; оракул — порог не выполнен или не запускается на результате.
   - **Unknown** — свидетельств не хватает, чтобы решить; допустим на любом пункте. Напиши, чего не хватает.
   - **н.п.** — пункт неприменим по правилу из рубрики, не по твоему выбору.
3. Порядок действий исполнителя — только по выписке действий, не по его рассказу.
4. Оракул запускаешь сам, на результате каждого пакета.
5. Сравни результаты по сути задачи: X лучше / Y лучше / равны / Unknown, с основанием. Длина и оформление пакета — не основание.
6. В этом же ответе — итог. Оценка 0–1 = pass / (pass + fail + Unknown) по пунктам без «н.п.». Итог задачи: fail — если хоть одно условие «Провал» или оракул — fail; pass — если все они pass; иначе Unknown.

**Формат вывода** — как `evals/runs/2026-10-21-gate/scoring/T3-score.md`, с итоговым блоком:

```
## 1. Условия «Провал»       таблица: условие | X | Y; в ячейке — значение и свидетельство
## 2. Строки карты оценки    по пакету: P1 pass — свидетельство; …
## 3. Оракул                 по пакету: команда → число → pass / fail
## 4. Сравнение по сути      X лучше | Y лучше | равны | Unknown — основание

ИТОГ <ID>
X: оценка=0.00 (pass N, fail N, Unknown N, н.п. N); провалы=[…]; задача=pass | fail | Unknown
Y: …
по сути: X лучше | Y лучше | равны | Unknown
слепота: соблюдена | нарушена — чем
```
