# Эталонные решения тестовых задач

Эталон — решение задачи из `evals/tasks.md`, которое проходит все её условия «Провал» и скрытый оракул, если он у задачи есть. Он доказывает две вещи: задача решаема, а грейдеры настроены — правильное решение они принимают. Методика — Anthropic, [Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents): «a 0% pass rate across many trials (i.e. 0% pass@100) is most often a signal of a broken task, not an incapable agent»; «For each task, it’s useful to create a reference solution: a known working output that passes all graders».

Эталон описывает, что сделано и сдано, а не какая роль это делала. В v0.2 планировщик и воркер сольются в одного исполнителя, а эталон от этого не меняется. `prompt.md` в эталоне — план с входной проверкой, записанный до выполнения; кто его пишет, неважно.

Это данные, а не инструкции харнесса: `tools/lint-harness.py` не считает `evals/reference/` файлами харнесса, у них нет английской пары и бюджета слов. Язык эталонов — русский, как у записанных прогонов.

## Как пользоваться

- **До прогона — доказать решаемость.** `tools/gate-check.py` на `prompt.md` и `journal.md` эталона возвращает 0 (кроме L1 — почему, сказано в его эталоне). Оценщик, получив эталон как обычный пакет без пометки, ставит pass на всех условиях «Провал». Если нет — чинят задачу или рубрику, а не исполнителя.
- **Во время прогона — не показывать.** Ни исполнителям (они получили бы ответ), ни оценщику (он подгонял бы оценку под образец, `evals/scorer.md`). Плечам дают копию материалов, а не этот репозиторий.
- **После прогона.** Отличие результата от эталона — не провал: провал определяют только условия задачи. Эталон помогает разобрать, почему условие сработало.
- **Синтетика.** Где материалов в задаче нет, эталон показывает действия до их получения и форму результата. Маленькие наборы, на которых видно, что критерий вычисляется, помечены «синтетика для эталона».

## Что в каждом эталоне

`reference.md`: разбор — тип задачи, цель за постановкой, две планки, входная проверка с пятью атрибутами из `core/gate.md` или честное «проверки нет»; вопросы человеку, не больше трёх; первые действия исполнителя по порядку; что сдаётся; самопроверка — каждое условие «Провал» и «Ожидается» из `evals/tasks.md` → выполнено / как видно. Рядом — сданные артефакты: план, журнал, результат.

## In English, briefly

A reference solution passes every failure condition of its task in `evals/tasks.md` and the hidden oracle, if there is one: it proves the task is solvable and the graders accept a correct answer. References describe what is done and delivered, not which role did it. Use them before a run to check the task and graders; never show them to the arms or the scorer. Ready: T1, T4, T5, T6, L1 (in Russian; synthetic materials are labelled). T2, T2-pass, T3 and L2 will be added separately.
